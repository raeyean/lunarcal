This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

LunarCal is a React Native lunar calendar app built with Expo (managed workflow). It targets iOS, Android, and Web. Core features: monthly calendar view, full-day lunar detail (Ganzhi 天干地支, Yi/Ji 宜忌, Tongshu 通書), auspicious date finder, and push notifications for lunar 初一/十五.

## Tech Stack

### Mobile (Expo app)
- **Expo 58** (managed workflow, no ejected native code; `ios/` and `android/` are generated by `npx expo prebuild` and gitignored)
- **React 19.3.0** / **React Native 0.88.1**
- **TypeScript 6.0** with strict mode (`tsconfig.json` extends `expo/tsconfig.base`)
- **React Native New Architecture** (always on since SDK 55; the Legacy Architecture is gone)
- **iOS**: minimum deployment target 16.4; UIKit scene life cycle (`SceneDelegate.swift`, `UIApplicationSceneManifest`), required by iOS 27
- **expo-splash-screen** — splash image and colours are configured in its plugin entry in app.json (top-level `splash` was removed in SDK 56)
- **lunar-javascript** v1.7.7 — core lunar calendar engine (Solar ↔ Lunar, Ganzhi, Jieqi, Yi/Ji)
- **react-native-reanimated 4** (+ `react-native-worklets`) — animations; **react-native-gesture-handler** — gestures (root wrapped in `GestureHandlerRootView`)
- **TanStack Query** — API data fetching with `staleTime=Infinity` (data is deterministic per date)
- **expo-notifications** + **expo-background-fetch** — notification scheduling
- **AsyncStorage** — persists theme, notification settings, zodiac preference

### Backend (API)
- **Hono** + **@hono/zod-openapi** — REST API with auto-generated OpenAPI spec + Swagger UI
- **Firebase Functions Gen 2** (`asia-east1`) — serverless host, public invoker
- **Zod** — shared request/response schemas between API and mobile
- **esbuild** — bundles `packages/shared` into self-contained `lib/index.js` for Cloud Build
- **Vitest** — 14 API route tests (routes, schemas, error paths, CORS preflight)

## Common Commands

```bash
# Mobile
npm start          # Start Expo dev server
npm run ios        # Run on iOS simulator (Expo CLI 58 supports Xcode 27's Device Hub)
npm run android    # Run on Android emulator
npm run web        # Run in web browser
npx expo lint      # Run ESLint

# iOS without Expo CLI (Release build embeds the JS bundle, so no Metro needed)
npx expo prebuild --clean -p ios
xcodebuild -workspace ios/LunarCal.xcworkspace -scheme LunarCal -configuration Release \
  -sdk iphonesimulator -destination 'id=<simulator UDID>' -derivedDataPath ios/build build
xcrun simctl install <UDID> ios/build/Build/Products/Release-iphonesimulator/LunarCal.app
xcrun simctl launch <UDID> com.raeyean.LunarCal

# API
npm run emulator              # Firebase emulator + esbuild watch
npm test -w @lunarcal/api     # Run Vitest tests

# Shared
npm test -w @lunarcal/shared  # Run shared package Vitest tests
npm test                      # Run all workspace tests (api + shared)
```

## Navigation Model

No navigation library. App.tsx manages screen state directly:
- `activeTab: 'daily' | 'calendar'` — switches between DailyDetailScreen and CalendarScreen
- `year/month/selectedDay` — shared date state passed as props
- AuspiciousFinderScreen and SettingsModal are modal overlays controlled by `visible` props

## Key Patterns

- **Theming**: `useTheme()` hook from ThemeContext provides `colors`, `isDark`, `toggleTheme`
- **Swipe navigation**: `useSwipeGesture(onPrev, onNext)` returns PanResponder props
- **Lunar data**: All lunar calculations go through `@lunarcal/shared` (lunar-javascript wrapper); `src/utils/lunar.ts` re-exports from there
- **Motion**: tokens in `src/constants/motion.ts`, use `useMotion()` for reduced-motion-aware configs.
- **API data**: `src/api/hooks.ts` TanStack Query hooks; base URL from `EXPO_PUBLIC_API_TRIGGER_URL` env var, falls back to production URL
- **Shared schemas**: Zod schemas in `packages/shared/src/schemas/` are the source of truth for API shapes — both API routes and mobile client import from there
- **Fonts**: Outfit (headings) and Inter (body) loaded in App.tsx via `useFonts`; all components assume fonts are loaded before rendering

## Platform Notes

- **iOS**: Tablet support enabled; uses compact DateTimePicker in settings
- **Android**: Edge-to-edge (mandatory since SDK 55), adaptive icon configured, predictive back gesture disabled
- **Lint**: `eslint.config.js` downgrades the React Compiler hook rules (`react-hooks/refs`, `set-state-in-effect`, `preserve-manual-memoization`) to warnings until existing code is migrated
- **Web**: Favicon configured; layout is portrait-optimised (not responsive for desktop widths)

## Known Gaps / Future Work

- No mobile UI test runner (Jest, Detox) — pure-fn code in `@lunarcal/shared` has Vitest coverage; mobile screens rely on manual QA
- Web layout not optimised for desktop/tablet widths
- Notification background fetch may be killed by Android battery optimisation; foreground fallback on app resume is in place via AppState listener

## PR Evidence

Every PR must include screenshots as evidence that the change works. A PR without them isn't ready for review.

- **What to capture:** each screen or state the change affects, in its final working state. Where it matters, include before and after shots, or light and dark mode. Use test data only: the repo is public, so a screenshot must never show personal information.
- **How to capture:**
  - Web: run Playwright (installed in a scratch directory, never added to the project) against `npx expo export -p web` output.
  - iOS simulator: `xcrun simctl io <UDID> screenshot <file>.png`.
  - Android emulator: `adb exec-out screencap -p > <file>.png`.
- **How to upload:** GitHub has no attachment API for `gh`, so screenshots live on the orphan branch `pr-assets`, under `pr/<PR number>/`. They never go on `main` or the feature branch. Use a worktree so the current branch isn't touched:
  ```bash
  git fetch origin pr-assets 2>/dev/null \
    && git worktree add /tmp/pr-assets pr-assets \
    || { git worktree add --detach /tmp/pr-assets && git -C /tmp/pr-assets switch --orphan pr-assets; }
  mkdir -p /tmp/pr-assets/pr/<N> && cp <screenshots> /tmp/pr-assets/pr/<N>/
  git -C /tmp/pr-assets add . && git -C /tmp/pr-assets commit -m "evidence: PR #<N>" && git -C /tmp/pr-assets push -u origin pr-assets
  git worktree remove /tmp/pr-assets
  ```
- **How to embed:** add a `## Screenshots` section to the PR body (`gh pr edit <N> --body ...`) with `![caption](https://raw.githubusercontent.com/raeyean/lunarcal/pr-assets/pr/<N>/<file>.png)` and one line saying what each shot proves.
- **Changes with no UI** (API, shared package, tooling): screenshots don't apply. Paste the verification commands and their output under `## Evidence` instead, and say there's no UI.
